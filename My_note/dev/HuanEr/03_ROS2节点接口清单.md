## 3. 服务（4 个）

| 服务 | 类型 | 作用 | 备注 |
| --- | --- | --- | --- |
| `~/bus_servo/get_state` | `GetBusServoState` | **读实测状态**（id/位置/偏差/温度/限位） | 用 `ReentrantCallbackGroup`；**每个舵机一次串口往返 ≈6 ms** |
| `~/pwm_servo/get_state` | `GetPWMServoState` | PWM 舵机状态 | 无效 |
| `~/move_stepper` | `MoveStepper` | 步进电机 | 无效 |
| `~/init_finish` | `std_srvs/Trigger` | **启动完成握手**（上电流程用） | 我们用它判断"驱动就绪" |

### `get_state` 请求用法
```
cmd: [ {id: 6, get_position: 1}, {id: 5, get_position: 1}, ... ]
```
可设的位：`get_id` / `get_position` / `get_offset` / `get_temperature` / `get_position_limit`
（`get_voltage` 在厂商代码里**被注释掉**）

> ⚠️ 服务回调在 `ReentrantCallbackGroup` 上 → **可并发**。原 SDK 的读是"无超时阻塞 + 单槽队列"，
> 并发下会互相偷回包 / 永久卡死（已在本工作区修复，见 [02](02_Python_SDK功能清单.md) §2.3）。

## 5. 上电流程与已知问题

**启动顺序（`__init__`）**
1. 打开串口（本工作区：失败自动重试 30×1s）
2. 创建话题/服务（全部用 `ReentrantCallbackGroup` 或 `timer_cb_group`）
3. `pwm_servo_set_offset(1, 0)`、`set_motor_speed([[1,0]…[4,0]])`
4. 启动 `pub_callback` 线程（每 20 ms 上报）
5. 提供服务 `~/init_finish`
6. 打印 `start`

**厂商已知问题**

| 问题 | 说明 |
| --- | --- |
| `pub_button_data` 用了未 import 的 `PacketReportKeyEvents` | 潜在 `NameError` |
| 节点退出重复调 `rclpy.shutdown()` | 无害报错 |
| `get_state` 的读**无超时** | 已修复 |
| `bus_servo_enable_torque` 的 `0x0B`/`0x0C` 写反 | 已修复 |
| PWM/OLED/传送带/步进接口存在但**固件不支持** | 建议标注或删除 |
