## 2. 命令分发（`packet_handle.c`）

`packet_handle_init()` 注册的 func（**只有 4 个**）：

```c
packet_register_callback(PACKET_FUNC_LED,       packet_led_handle);        ✅
packet_register_callback(PACKET_FUNC_BUZZER,    packet_buzzer_handle);     ✅
packet_register_callback(PACKET_FUNC_BUS_SERVO, packet_serial_servo_handle); ✅
packet_register_callback(PACKET_FUNC_MOTOR,     packet_motor_handle);      ✅
// packet_register_callback(PACKET_FUNC_PWM_SERVO, packet_pwm_servo_handle); ❌ 被注释
```

> ❗ **PWM 舵机的处理函数写好了但没有注册** —— 宿主机发 PWM 舵机命令**不会生效**。
> 同理 `OLED / CONVEYOR / STEPPER_MOTOR` 只是 Python SDK 里较新版本的扩展，本固件不认。

### 各 func 的子命令

| func | sub | 功能 |
| --- | --- | --- |
| **LED(1)** | — | `{led_id(1~2), on_time, off_time, repeat}` → `led_flash()` |
| **BUZZER(2)** | — | `{freq, on_time, off_time, repeat}` → `buzzer_didi()` |
| **BUS_SERVO(5)** | `0x01`~`0x3A` 共 19 个 | 见 [01](01_主机-STM32协议.md) §3（**权威表**） |
| **MOTOR(3)** | `0` | 单个电机控制 |
| | `1` | 多个电机控制 |
| | `2` | 单个电机停止 |
| | `3` | 多个电机停止 |
| | `0x20` | 直接控制 PWM |
| **PWM_SERVO(4)**<br>*（未注册）* | `0x01` / `0x03` / `0x05` / `0x07` / `0x09` | 多个控制 / 单个控制 / 读位置 / 设偏差 / 读偏差 |

## 3. 回包机制

`packet_serial_servo_report_init()` 组装 `PacketReportSerialServoTypeDef`：

```c
report->servo_id    = servo_id;
report->sub_command = cmd;
report->success     = (int8_t)success;   // 0 = 成功
// args[8] 由各 case 填
```

由各 case 用 `packet_transmit(&packet_controller, PACKET_FUNC_BUS_SERVO, &report, N)` 发出：

| sub | 回包长度 |
| --- | --- |
| `0x01` 设位置 | **不回包**（实测确认） |
| `0x03` 停止 / `0x10` / `0x20` / `0x24` / `0x30` / `0x34` / `0x38`（写类） | 4 字节 |
| `0x05` / `0x07` / `0x0D` / `0x12` / `0x22` / `0x3A`（读类，单值） | 4~5 字节 |
| `0x32` / `0x36`（读类，双值限位） | **7 字节** |

## 4. 周期上报（固件主动发，非应答）

`packet_transmit` 在全树的调用点：

| 位置 | func | 触发 |
| --- | --- | --- |
| `System/app.c:28` | `PACKET_FUNC_KEY`(6) | 按键事件 |
| `Portings/imu_porting.c:44` | `PACKET_FUNC_IMU`(7) | IMU 采样 |
| `System/packet_handle.c` ×9 | `PACKET_FUNC_BUS_SERVO`(5) | 命令应答 |
| **（未找到）** | `PACKET_FUNC_SYS`(0) 的 `sub_cmd=0x04` 电池包 | — |

> ⚠️ **电池电压广播**：`packet_reports.h` 里有 `PacketReportBatteryVoltageTypeDef{sub_cmd; uint16_t voltage}`，
> 但**源码树里找不到发送点**（可能在 `JetArmController_v1.0.pkg` 里或不同固件版本）。
> 实测：板子**持续周期性发送** `AA 55 00 03 04 82 1E 2A`（sub_cmd=0x04，7810 mV = 7.810 V）。
> `PACKET_FUNC_GAMEPAD` / `PACKET_FUNC_SBUS` 同样只见类型定义，未见发送点。

## 6. 对"重写/优化"的启示

| 发现 | 含义 |
| --- | --- |
| 固件只认 4 个 func | 上位机**不需要**实现 PWM/OLED/传送带/步进 —— 删掉能少 4~5 个方法 |
| 写命令多数回 4 字节、`0x01` 不回包 | 客户端**不能假设每个命令都有响应**；读要自带超时（已修） |
| 读类命令 19 个里 9 个是"读" | 读路径是唯一的性能瓶颈（6 舵机 35ms ≈ 28 Hz） |
| 存在无法在源码中定位的周期上报（电池） | 接收端必须**按帧解析 + 逐帧跳过**，不能只匹配自己的回包 |
| 电池包 `sub_cmd=0x04` | 可作为一个"链路活着"的心跳信号使用 |
| 固件源码只有 STM32F4 工程，固件逻辑改动需重编译（Keil/CMake） | ⚠️ **不要试图改固件**，所有优化都放在主机侧 |
