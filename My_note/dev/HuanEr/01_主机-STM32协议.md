# 01 · 主机 ↔ STM32 协议

> 两层协议：**主机↔STM32**（本文档）与 **STM32↔舵机**（§5）。
> 依据：`STM32/JetArmF4_Firmware/Hiwonder/Misc/packet.h`、`checksum.c`、`System/packet_handle.c`

---

## 1. 帧格式

```
AA 55 | func(1B) | len(1B) | data(len B) | crc8(1B)
```

| 项 | 说明 |
| --- | --- |
| 帧头 | `0xAA 0x55` |
| `func` | 功能码，见 §2 |
| `len` | **data 区**字节数（不含头/len/crc） |
| `crc8` | `crc8(func, len, data...)` —— **不含 `AA 55`**；查表法，见 `checksum.c` |

**总长 = 5 + len**

### 请求/响应

- 命令由主机下发；STM32 对**部分**命令回一条同 `func` 的包
- 回包 data 布局（总线舵机）：`servo_id | sub_command | success | args[8]`
  （对应 SDK 的 `struct.unpack("<BBb...")`）
- ⚠️ **`set_position` 不回包**（实测：写 1 次 → 收到 0 个回包）
- ⚠️ STM32 还会**周期性地主动上报**，见 §4

### 实测样例（逐字节解析）

```
AA 55 00 03 04 82 1E 2A
│  │  │  │  └──┴─ data: 04 82 1E
│  │  │  └──────── len = 3
│  │  └─────────── func = 0 (SYS)
│  └────────────── 帧头
└───────────────── CRC8 = 0x2A ✓

data = 04 | 82 1E   →  sub_cmd=0x04(电池) + uint16 LE 0x1E82 = 7810 → 7.810 V
```

## 2. func 码表（`enum PACKET_FUNCTION`）

| 值 | 名称 | 本版固件是否注册 | 说明 |
| --- | --- | --- | --- |
| 0 | `PACKET_FUNC_SYS` | ✅（上报） | 系统上报，电池电压等 |
| 1 | `PACKET_FUNC_LED` | ✅ | 板载 LED |
| 2 | `PACKET_FUNC_BUZZER` | ✅ | 蜂鸣器 |
| 3 | `PACKET_FUNC_MOTOR` | ✅ | 直流/编码电机 |
| 4 | `PACKET_FUNC_PWM_SERVO` | ❌ **未注册** | 本固件注释掉了 |
| 5 | `PACKET_FUNC_BUS_SERVO` | ✅ | **总线舵机（本项目主要用）** |
| 6 | `PACKET_FUNC_KEY` | ✅（上报） | 按键事件 |
| 7 | `PACKET_FUNC_IMU` | ✅（上报） | IMU |
| 8 | `PACKET_FUNC_GAMEPAD` | — | 手柄（上报，源码树内未见发送点） |
| 9 | `PACKET_FUNC_SBUS` | — | SBus（同上） |
| 10 | `PACKET_FUNC_NONE` | — | 本固件的"非法"边界 |

> ⚠️ **Python SDK 的 `PACKET_FUNC_NONE = 14`**，且含 `OLED / CONVEYOR / STEPPER_MOTOR` 等 —— SDK 比这块固件新，**那些方法在本板上无效**。

## 3. `PACKET_FUNC_BUS_SERVO`(5) 子命令全表

来自固件 `packet_serial_servo_handle()` 的 switch（权威）：

| sub | 方向 | 功能 | 对应 SDK 方法 |
| --- | --- | --- | --- |
| `0x01` | 写 | 舵机控制（**设位置**，带 duration） | `bus_servo_set_position` |
| `0x03` | 写 | 停止舵机 | `bus_servo_stop` |
| `0x05` | **读** | 位置读取 | `bus_servo_read_position` |
| `0x07` | **读** | 输入电压读取 | `bus_servo_read_vin` |
| `0x09` | **读** | 温度读取 | `bus_servo_read_temp` |
| `0x0B` | 写 | **卸载动力（卸力）** | `bus_servo_enable_torque(False)` |
| `0x0C` | 写 | **加载动力（保持）** | `bus_servo_enable_torque(True)` |
| `0x0D` | **读** | 动力状态读取 | `bus_servo_read_torque_state` |
| `0x10` | 写 | ID 写入 | `bus_servo_set_id` |
| `0x12` | **读** | ID 读取 | `bus_servo_read_id` |
| `0x20` | 写 | 位置偏差调整 | `bus_servo_set_offset` |
| `0x22` | **读** | 位置偏差读取 | `bus_servo_read_offset` |
| `0x24` | 写 | 位置偏差保存（写 Flash） | `bus_servo_save_offset` |
| `0x30` | 写 | 位置（角度）限制设置 | `bus_servo_set_angle_limit` |
| `0x32` | **读** | 位置（角度）限制读取 | `bus_servo_read_angle_limit` |
| `0x34` | 写 | 电压限制设置 | `bus_servo_set_vin_limit` |
| `0x36` | **读** | 电压限制读取 | `bus_servo_read_vin_limit` |
| `0x38` | 写 | 温度限制设置 | `bus_servo_set_temp_limit` |
| `0x3A` | **读** | 温度限制读取 | `bus_servo_read_temp_limit` |

### 3.1 `0x01` 设位置的 data 布局（压测/直连用）

```
data = 01 | dur_lo dur_hi | n | (id, pos_lo, pos_hi) × n
```
- `dur` 单位 **ms**（小端），`pos` 0~1000（小端）
- `n` = 本次控制的舵机个数

**现算样例**（CRC 由 SDK 的 `checksum_crc8` 生成，可直接用于串口终端）：

| 用途 | 十六进制 |
| --- | --- |
| 写 1 个舵机 `id6→500, 40ms` | `AA 55 05 07 01 28 00 01 06 F4 01 5E` |
| 写 6 个舵机 `全500, 40ms` | `AA 55 05 16 01 28 00 06 01 F4 01 02 F4 01 03 F4 01 04 F4 01 05 F4 01 06 F4 01 62` |
| 读 1 个舵机位置 `id6` | `AA 55 05 02 05 06 EC` |
| 卸力 `id6` | `AA 55 05 02 0B 06 30` |
| 保持 `id6` | `AA 55 05 02 0C 06 5E` |

### 3.2 `0x03` 停止舵机
单个：`data = 03 | id`；多个：见固件 `bus_servo_stop([...])` 的打包方式。

## 4. 周期上报（STM32 → 主机，非应答）

| func | sub_cmd | 结构体（`packet_reports.h`） | 源码里是否找到发送点 | 实测 |
| --- | --- | --- | --- | --- |
| 0 SYS | `0x04` | `{ sub_cmd; uint16_t voltage; }` | ❌ 未找到（只有类型定义） | ✅ 实测 7.810 V，**周期性持续发送** |
| 6 KEY | — | `{ key_id; event; }` | ✅ `System/app.c` | — |
| 7 IMU | — | 加速度/角速度 float×6，或四元数 | ✅ `Portings/imu_porting.c` | — |
| 8 GAMEPAD | — | `{ buttons; hat; lx,ly,rx,ry; }` | ❌ 未找到 | — |
| 9 SBus | — | `{ channels[16]; ch17; ch18; ... }` | ❌ 未找到 | — |

> ⚠️ 接收端必须按 `AA 55 + func + len + CRC` **逐帧跳过**，不能假设收到的都是自己的回包。
> 电池包会混在舵机回包之间。

### 4.1 全部上报结构体（`Portings/packet_reports.h`）

```c
PacketReportBatteryVoltageTypeDef { uint8_t sub_cmd; uint16_t voltage; }          // 实测 0x04
PacketReportKeyEventTypeDef       { uint8_t key_id; uint8_t event; }
PacketReportIMU_Raw_TypeDef       { float accel[3]; float gyro[3]; }
PacketReportIMU_Quat_TypeDef      { float w,x,y,z; }
PacketReportSerialServoTypeDef    { uint8_t servo_id; uint8_t sub_command;
                                    uint8_t success; uint8_t args[8]; }             // ← 舵机回包
PacketReportPWMServoTypeDef       { uint8_t servo_id; uint8_t sub_command; uint8_t args[8]; }
PacketReportGamepadTypeDef        { uint16_t buttons; uint8_t hat;
                                    int8_t lx,ly,rx,ry; }
PacketReportSBusTypeDef           { int16_t channels[16]; uint8_t ch17,ch18;
                                    uint8_t signal_loss; uint8_t fail_safe; }
```

## 5. 第二层：STM32 ↔ 总线舵机（舵机原生协议）

`Hiwonder/Peripherals/serial_servo.h`：帧头 `0x55`，命令码如下（LX 系列总线舵机标准）：

| 码 | 名称 | 码 | 名称 |
| --- | --- | --- | --- |
| 1 | MOVE_TIME_WRITE | 20 | ANGLE_LIMIT_WRITE |
| 2 | MOVE_TIME_READ | 21 | ANGLE_LIMIT_READ |
| 7 | MOVE_TIME_WAIT_WRITE | 22 | VIN_LIMIT_WRITE |
| 8 | MOVE_TIME_WAIT_READ | 23 | VIN_LIMIT_READ |
| 11 | MOVE_START | 24 | TEMP_MAX_LIMIT_WRITE |
| 12 | MOVE_STOP | 25 | TEMP_MAX_LIMIT_READ |
| 13 | ID_WRITE | 26 | TEMP_READ |
| 14 | ID_READ | 27 | VIN_READ |
| 17 | ANGLE_OFFSET_ADJUST | 28 | **POS_READ** |
| 18 | ANGLE_OFFSET_WRITE | 29 | OR_MOTOR_MODE_WRITE |
| 19 | ANGLE_OFFSET_READ | 30 | OR_MOTOR_MODE_READ |
| | | 31/32 | LOAD_OR_UNLOAD_WRITE/READ（扭矩） |
| | | 33/34 | LED_CTRL_WRITE/READ |
| | | 35/36 | LED_ERROR_WRITE/READ |

> **注意**：主机侧的 `0x05`(读位置) ≠ 舵机侧的 `28`(POS_READ)。
> STM32 负责翻译，所以**改主机侧子命令不需要懂舵机协议**。

另：`CMD_SERVO_MOVE 0x03`（`serial_servo.h`）—— 舵机内部批量执行命令。

## 6. 串口参数

| 项 | 值 |
| --- | --- |
| 波特率 | `1000000`（驱动默认） |
| 格式 | 8N1，无流控 |
| 帧解析缓冲 | `PACKET_PARSE_BUFFER_SIZE = 64` |
| 实测耗时 | 读 **1 个舵机 ≈6 ms**；**6 个 ≈35 ms** → 读路径天花板 ≈28 Hz |
