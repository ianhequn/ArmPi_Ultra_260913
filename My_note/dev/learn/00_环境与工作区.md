# 00 环境与工作区

> 目标：知道代码放哪、怎么构建、怎么运行。

---

## 步骤

### 1. 认识工作区结构

```bash
cd /home/u24/MyTest/dev01/ros2/test_ws01
ls
```
```
src/        # ROS2 包（唯一被 git 跟踪的代码区）
My_note/    # 文档/教程
build/ install/ log/   # colcon 产物（不用管，可删可重建）
```

### 2. 每次开终端先 source

```bash
source /opt/ros/jazzy/setup.bash          # ROS2 本体
source /home/u24/MyTest/dev01/ros2/test_ws01/install/setup.bash   # 本工作区
```

> 不 source 会报 `package not found` / `message type invalid`。

### 3. 构建

```bash
cd /home/u24/MyTest/dev01/ros2/test_ws01
colcon build                             # 全部
colcon build --packages-select <pkg>     # 指定包（快）
source install/setup.bash                # 构建后重新 source
```
预期：`Summary: N packages finished`。

### 4. 测试（lint + 单测）

```bash
colcon test --packages-select <pkg>
colcon test-result --verbose
```
预期：`0 failures`。

### 5. 跑一个节点

```bash
ros2 run <pkg> <节点名>
```

---

## 原理（极简）

- ROS2 工作区 = `src/`（源码） + `build/install/log`（产物）。
- `colcon build` 把包**安装**到 `install/`；`ros2 run/launch` 从 `install/` 找。
- `source install/setup.bash` 是把 `install/` 加进环境变量，让 ROS2 认识你的包。

## 常见坑

- 改了代码**没重新 `colcon build`** → 跑的还是旧版。
- 新终端**忘了 source** → 找不到包/类型。
- `build/install/log` 删了没事，`colcon build` 会重建。
