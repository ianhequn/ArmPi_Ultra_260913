# 09 调试与排错

> 目标：出问题按这套流程定位。

---

## 通用排查顺序

```bash
ros2 node list                 # 节点在不在
ros2 topic list                # 话题在不在
ros2 topic hz <topic>          # 有没有持续数据
ros2 topic echo <topic> -n 1   # 内容对不对
ros2 service list              # 服务在不在
ros2 interface show <type>     # 字段对不对
```

## 常见故障表

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `package not found` | 没 source | `source install/setup.bash` |
| 话题存在但没数据 | 上游没起 / 舵机没电 | 查 driver、开舵机电源 |
| `get_state` 卡住不返回 | 舵机总线无响应（**读无超时**） | 查舵机电源；重启 driver |
| 串口 `Input/output error` | CH340 在 VM 下掉线 | 等几秒 / 重新插拔（驱动自动重连） |
| 日志看着不刷 | `ros2 launch` 管道块缓冲 | 代码里 `print(..., flush=True)` |
| 发了命令没效果 | 消息在订阅前发出（丢包） | 等就绪信号再发，或连发两次 |
| 动作转错方向/幅度 | 单位写错、关节配了反向 | 查 `position_unit`、yaml 的 `min/max` |

## 真实踩过的坑

1. **启动时序竞争**：`dataset_stream` 在 driver 起来前发扭矩关 → 消息丢失。改为等 `init_finish` 服务。
2. **`Node._clients` 撞名**：自定义属性与 rclpy 内部重名 → 运行崩溃。
3. **厂商 SDK bug**：`bus_servo_enable_torque` 的 `0x0B/0x0C` 写反 → 卸不了力，对调后正常。
4. **读无超时**：舵机不回就永久卡住并占锁 → 建议加 `timeout`。

## 串口设备排查

```bash
ls -l /dev/ttyUSB*
ls -l /dev/serial/by-id/     # 两个 CH340 ID 相同 → 会冲突
ls -l /dev/serial/by-path/   # 用这个区分物理口
udevadm info -q property -n /dev/ttyUSB0
fuser -v /dev/ttyUSB0        # 谁占着串口
```

## 后台跑节点（别用 SIGKILL）

- 用 `subprocess.Popen(start_new_session=True)`，退出时对整组发 `SIGINT`。
- `SIGKILL` 易让串口变 `EIO`，需要重新插拔。
