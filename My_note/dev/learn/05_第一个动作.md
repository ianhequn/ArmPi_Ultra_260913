# 05 第一个动作

> 目标：端到端跑通——driver + 网关起来，发一条话题，机械臂真的动。

---

## 步骤

### 1. 终端 A：驱动

```bash
cd /home/u24/MyTest/dev01/ros2/test_ws01
source /opt/ros/jazzy/setup.bash && source install/setup.bash
ros2 launch ros_robot_controller ros_robot_controller.launch.py
```
预期：`[ros_robot_controller]: start`

### 2. 终端 B：网关

```bash
source /opt/ros/jazzy/setup.bash && source install/setup.bash
ros2 launch servo_controller servo_controller.launch.py
```
预期：`[servo_manager]: start`、`[controller_manager]: start`

### 3. 终端 C：先体检

```bash
ros2 node list
ros2 topic list | grep -E "servo|joint"
ros2 topic hz /ros_robot_controller/battery     # 板子在发数据吗
```
预期：`battery` 有约 9~10Hz 的数据。没有就是串口/板子问题（看第 09 章）。

### 4. 发动作

```bash
ros2 topic pub --once /servo_controller servo_controller_msgs/msg/ServosPosition \
  "{duration: 1.0, position_unit: 'pulse', position: [{id: 6, position: 700}]}"
```
预期：joint1（id 6）用 1s 转到 700。

### 5. 一键启动全部（省事）

```bash
ros2 launch arm_lerobot_dataset_stream arm_lerobot_dataset.launch.py
```
这个 launch 会把 **driver + 网关 + 数据流**一起起来。

---

## 原理（极简）

- 数据流：`话题 → 网关 → 驱动 → 串口 → 板子 → 舵机`。
- `duration` = 运动时长（秒），越大越慢。
- 板子会持续上报电池/IMU，可用来判断"板子活着"。

## 常见坑

- **舵机电源必须开**（板子有电 ≠ 舵机有电）；没开时读操作会卡住。
- 先 driver 后网关，顺序反了会找不到服务。
- 改了代码记得 `colcon build` + 重新 source。
