# 06 宿主串口桥：arm_serial_bridge

> 目标：另一台设备通过**串口**发文本命令控制机械臂。
> 对应代码：`src/arm_serial_bridge/`

---

## 拓扑

```mermaid
flowchart LR
  H["宿主机 host_arm.py"] -- 文本命令 --> U1["/dev/ttyUSB1"]
  U1 --> B["serial_bridge 节点"]

```

## 命令（ASCII，以 `\n` 结尾）

| 命令 | 作用 |
| --- | --- |
| `PING` | 探活 |
| `Q` | 返回**缓存**角度 |
| `R` | 返回**实测**角度 |
| `H` | 回初始位 |
| `A <关节> <角度> [时长ms]` | 转动 |
| `L` | 卸力 |
| `E` | 保持（重新带载） |

关节可以用名字（`joint1`）或 id。

## 原理（极简）

- `protocol.py` 是**纯文本解析**（不含 ROS），所以能**单独单测**。
- `serial_bridge.py` 是 ROS 节点：串口收行 → 转话题/服务调用 → 回包写回串口。
- `split_commands()` 解决"多条命令粘在一个包里"。

## 常见坑

- 两个 CH340 的 `ID_SERIAL` 相同 → `/dev/serial/by-id` 会冲突，用 `/dev/ttyUSB0/1`（按插入顺序）。
- 命令结尾必须有 `\n` 或 `\r`。
- 宿主机口默认 `115200`，别和机械臂口 `1000000` 搞混。
- 发送 `L`（卸力）时电流冲击大，偶发 USB 掉线；驱动会自动重连。
