# 06 宿主串口桥：arm_serial_bridge

> 目标：另一台设备通过**串口**发文本命令控制机械臂。
> 对应代码：`src/arm_serial_bridge/`

---


## 命令（ASCII，以 `\n` 或 `\r` 结尾）

串口桥**只支持这 4 个**：

| 命令 | 作用 | 应答 |
| --- | --- | --- |
| `PING` | 探活 | `PONG` |
| `Q` | **缓存**角度 | `STATE J1=.. J2=..`（度） |
| `H` | 回初始位（全 0°） | `OK H` |
| `A <关节> <角度>` | 转动 | `OK A ...` |
| `A J1 10 J5 40 T 800` | 多关节 + 时长(ms) | `OK ...` |

- **关节写法**：`J1`~`J5`、`G`（夹爪），或数字 `1`~`6`。
- **时长**：`T <毫秒>`，可省略（默认 500ms）。
- ⚠️ `R`（实测角度）/`L`（卸力）/`E`（保持）**只在 VOFA UDP 桥**里有，串口桥没有。

## 步骤

### 1. 启动

```bash
cd /home/u24/MyTest/dev01/ros2/test_ws01
source /opt/ros/jazzy/setup.bash && source install/setup.bash
ros2 launch arm_serial_bridge arm_serial_control.launch.py
```
参数：`arm_device=/dev/ttyUSB0`（机械臂）、`host_device=/dev/ttyUSB1`（宿主机口）。

### 2. 宿主机发命令

```bash
python3 src/arm_serial_bridge/scripts/host_arm.py --device /dev/ttyUSB1 A J5 23.3
python3 src/arm_serial_bridge/scripts/host_arm.py --device /dev/ttyUSB1 Q
python3 src/arm_serial_bridge/scripts/host_arm.py --device COM5 A J1 10 J5 40 T 800
```
预期：打印应答，如 `OK A J5 23.3` / `STATE J1=..`。

### 3. 不写代码直接测

```bash
python3 -c "
import serial, time
s = serial.Serial('/dev/ttyUSB1', 115200, timeout=0.3)
s.write(b'Q\n'); time.sleep(0.2)
print(s.read(200))
"
```
预期：`STATE J1=.. J2=.. ...`。

## 原理（极简）

- `protocol.py` 是**纯文本解析**（不含 ROS），所以能**单独单测**。
- `serial_bridge.py` 是 ROS 节点：串口收行 → 解析 → 转话题下发 → 回包写回串口。
- `split_commands()` 解决"多条命令粘在一个包里"。

## 常见坑

- 两个 CH340 的 `ID_SERIAL` 相同 → `/dev/serial/by-id` 会冲突，用 `/dev/ttyUSB0/1`（按插入顺序）。
- 命令结尾必须有 `\n` 或 `\r`。
- 宿主机口默认 `115200`，别和机械臂口 `1000000` 搞混。
- 关节别写成 `joint1`，串口协议只认 `J1`~`J5`/`G`/数字。
